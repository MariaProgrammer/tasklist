# Tasklist

**Tasklist** — fullstack-приложение для управления личными задачами. Пользователь может зарегистрироваться, войти в аккаунт и работать со своим списком задач: создавать задачи, просматривать их, отмечать выполненными и удалять.

Проект охватывает весь путь данных — от React-интерфейса и HTTP-запроса до Express API и PostgreSQL. Frontend опубликован на GitHub Pages, а backend и база данных развёрнуты в Docker на VPS.

**[Открыть приложение](https://mariaprogrammer.github.io/tasklist/)** · **[Проверить API](https://api.tasklist.fun/api/health/live)**

## Возможности

- Регистрация и вход с авторизацией через JWT.
- Персональный список задач для каждого пользователя.
- Создание задач с названием, приоритетом и сроком выполнения.
- Разделение задач на активные и завершённые.
- Сортировка по сроку выполнения и приоритету.
- Обновление и удаление задач.
- Получение данных профиля и удаление аккаунта.
- Проверки работоспособности и готовности API.

## Архитектура

```text
                         ┌──────────────────────────────┐
                         │         GitHub Pages         │
                         │       React + Vite SPA       │
                         └──────────────┬───────────────┘
                                        │ HTTPS-запросы
                                        ▼
Браузер ─────────────────► api.tasklist.fun
                                        │
                                        ▼
                                     Caddy
                              HTTPS / reverse proxy
                                        │
                                        ▼
                                Express REST API
                              авторизация и CRUD
                                        │
                                        ▼
                                  PostgreSQL 16
```

Статический frontend размещён отдельно от серверной части. На VPS Docker Compose управляет сервисами PostgreSQL, Express и Caddy. Caddy принимает HTTPS-запросы и передаёт их backend, сохраняя префикс `/api`.

PostgreSQL и порт Express не публикуются напрямую в интернет: взаимодействие браузера с серверной частью проходит через HTTPS-прокси.

## CRUD задач

| Действие | Метод | Маршрут |
|---|---|---|
| Создать задачу | `POST` | `/api/tasks` |
| Получить список задач | `GET` | `/api/tasks` |
| Получить задачу по ID | `GET` | `/api/tasks/:id` |
| Обновить задачу | `PATCH` | `/api/tasks/:id` |
| Удалить задачу | `DELETE` | `/api/tasks/:id` |

Запросы к задачам выполняются от имени авторизованного пользователя. Frontend передаёт JWT в заголовке:

```http
Authorization: Bearer <token>
```

Помимо CRUD задач, API предоставляет маршруты для работы с аккаунтом:

| Действие | Метод | Маршрут |
|---|---|---|
| Регистрация | `POST` | `/api/auth/register` |
| Вход | `POST` | `/api/auth/login` |
| Получение текущего пользователя | `GET` | `/api/auth/me` |
| Удаление профиля | `DELETE` | `/api/auth/profile` |

Для диагностики доступны `GET /api/health/live` и `GET /api/health/ready`.

## Как проходит запрос

Например, при создании задачи:

1. Пользователь заполняет форму в React-интерфейсе.
2. Frontend отправляет `POST /api/tasks` с данными задачи и JWT.
3. Express обрабатывает запрос и сохраняет задачу в PostgreSQL.
4. API возвращает созданную задачу.
5. React обновляет список без перезагрузки страницы.

Таким образом, интерфейс не хранит общий список задач как источник истины: данные поступают из API и сохраняются в базе данных.

## Работа с базой данных

Схема PostgreSQL хранится в `backend/migrations/001_initial_schema.sql`. При запуске backend проверяет подключение к базе данных и запускает миграции. Это позволяет разворачивать схему вместе с приложением и отслеживать её изменения в коде.

Для данных PostgreSQL используется постоянный Docker-том: пересоздание контейнера не должно удалять содержимое базы.

## Конфигурация и деплой

### Frontend

Frontend собирается Vite с базовым путём `/tasklist/`, соответствующим адресу GitHub Pages project site:

```text
https://mariaprogrammer.github.io/tasklist/
```

Production-сборка обращается к API по адресу:

```text
https://api.tasklist.fun/api
```

Для локальной проверки сборки из каталога frontend:

```bash
npm ci
npm run build
```

Публикация frontend выполняется через GitHub Actions. В репозитории GitHub Pages файлы frontend находятся в корне: рядом расположены `package.json`, `index.html`, `src/` и `public/`.

### Backend

На VPS приложение запускается через Docker Compose. Отдельные сервисы отвечают за PostgreSQL, Express API и Caddy. Caddy обеспечивает HTTPS для `api.tasklist.fun` и проксирует запросы к backend.

Серверная конфигурация использует переменные окружения для подключения к базе данных, JWT и разрешённого CORS origin. Пароли и секреты хранятся на сервере и не включаются в frontend-сборку или публичный репозиторий.

> Переменные `VITE_*` встраиваются в JavaScript, доступный браузеру. Они подходят для публичного URL API, но **не для секретов**.

## Структура проекта

```text
frontend/
├── public/                 # Публичные ресурсы
├── src/                    # React-приложение и API-клиент
├── index.html
├── vite.config.js
├── package.json
└── package-lock.json

backend/
├── migrations/
│   └── 001_initial_schema.sql
├── src/                    # Express API
└── Dockerfile

docker-compose.yml          # PostgreSQL, backend и Caddy

```

Frontend публикуется в отдельном репозитории GitHub Pages; backend и конфигурация сервисов размещаются на VPS.

## Что демонстрирует проект

- **Полный цикл fullstack-разработки:** интерфейс, API, база данных и развёртывание.
- **REST-подход к CRUD:** отдельные маршруты и HTTP-методы для операций над задачами.
- **Работу с авторизацией:** доступ к персональным данным через защищённые запросы.
- **Разделение компонентов:** статический frontend, сервер приложения, база данных и HTTPS-прокси решают разные задачи.
- **Воспроизводимое развёртывание:** контейнеры и SQL-миграции заменяют ручную настройку приложения и схемы БД.
- **Учёт production-окружения:** отдельный адрес API, CORS для GitHub Pages, HTTPS и отсутствие прямого публичного доступа к PostgreSQL.
